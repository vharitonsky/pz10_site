Практична 10 — персональне завдання

Аналіз складу залежностей (SCA), пошук витоків і складання звіту. Введіть свій user-id зі списку групи, виконайте завдання прямо на сторінці та завантажте відповіді у файл для здачі.

Що і як робити

Інструкція однакова для всіх. Персональні дані з'являться нижче після вводу user-id. CVE/CVSS шукаєте самі у зовнішніх базах — на сторінці їх немає.

  1. Тріаж залежностей. За маніфестом (package.json / requirements.txt) для кожної залежності визначте: вразлива (ця версія має відому CVE) чи безпечна. Перевіряйте версію у NVD, GitHub Advisory Database або Snyk.
  2. Критичність. Серед вразливих позначте критичні — з CVSS ≥ 9.0 (перевіряйте за CVSS-калькулятором FIRST.org).
  3. Пошук витоків. У наданих рядках код-пошуку позначте справжні секрети (ключі, токени, паролі, приватні ключі), відсіявши шум (публічні ключі, URL, прапорці конфігу).
  4. Звіт. Впишіть CVE найвищого пріоритету (найбільший CVSS) та безпечну версію, до якої оновити.
  5. Здача. Натисніть «Завантажити відповіді (JSON)» і прикріпіть файл до завдання. Самоперевірки тут немає — оцінює викладач.

Приклад (на сторонніх даних — не з вашого варіанту)

Тріаж: lodash 4.17.11 → у NVD є CVE-2019-10744 (CVSS 9.1) → вразлива та критична. express 4.18.2 → відомих CVE немає → безпечна.
Витоки: AWS_SECRET_ACCESS_KEY=… → справжній секрет. API_BASE_URL=https://… → не секрет (шум).
Звіт: найвищий CVSS у наборі — 9.8 (напр. CVE-2021-44906, minimist) → у звіт першим, оновити до безпечної версії.
